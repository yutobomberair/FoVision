# FoVision 仕様書(テーマ 1: チェッカーボードによるベースライン)

この文書の数値は**すべてシミュレーション由来**。実機(モジュール+Jetson)では未検証で、会社で確認する項目は末尾にまとめた。

## 1. 前提

| 項目 | 値 | 根拠 |
|---|---|---|
| 解像度 | 1920 x 1536 | モジュール仕様 |
| FoV | 202°(半画角 101°) | モジュール仕様 |
| 射影方式 | 等距離射影 r = f·θ | 仮定(データシート未入手) |
| イメージサークル | 水平いっぱい、垂直は見切れ | 利用者からの情報 |
| 公称焦点距離 | f = 960 / (101° をラジアンにした値) = 544.59 px | 上 2 行から算出 |
| 公称主点 | (959.5, 767.5) | 画像中心と仮定 |

この前提では垂直方向に写るのは光軸から約 ±81° まで。入射角 90° を超える領域は画像の左右端の帯(幅およそ 105 px ずつ)だけになる。

## 2. 投影モデル

モデル名: `kannala_brandt_equidistant_atan2`(`fovision/model.py`)

カメラ座標系は X 右、Y 下、Z 光軸前方。画素座標は画素中心が整数。

```
rho     = sqrt(X^2 + Y^2)
theta   = atan2(rho, Z)
theta_d = theta * (1 + k1 theta^2 + k2 theta^4 + k3 theta^6 + k4 theta^8)
u = fx * theta_d * X / rho + cx
v = fy * theta_d * Y / rho + cy
```

- 推定するパラメータは fx, fy, cx, cy, k1〜k4 の 8 個。k がすべて 0 なら純粋な等距離射影。
- Z > 0 の範囲では `cv2.fisheye` の (K, D)(skew = 0)と同じ定義なので、係数はそのまま相互に使える。
- `cv2.fisheye` との違いは θ を `atan2` で求める点だけ。これで入射角 90° 以上(Z ≤ 0)も扱える。
- レンズの実際の射影方式が等距離でなくても、差は k1〜k4 が吸収する想定(等立体角などでの確認は未実施)。

## 3. OpenCV の既存関数が使えるかの確認結果

`scripts/check_cv2_fisheye.py`(OpenCV 5.1.0、真値既知・ノイズ無しの往復テスト)。

| 対象 | 結果 |
|---|---|
| `cv2.fisheye.projectPoints` | 90° 未満は自前モデルと一致。90° 超は反対側に投影され、約 1711 px ずれる |
| `cv2.fisheye.undistortPoints` | 89° までは正しく戻る。90° 以上は出力形式(x/z)で原理的に表せない |
| `cv2.fisheye.calibrate` | 内部パラメータの初期値を与えないと失敗。与えれば全点 90° 未満のデータでは真値に一致。90° 超の点を含むビューがあると失敗 |
| `cv2.omnidir.calibrate` | 90° 超を含んでも動くが、一部のビューを捨て、ノイズ無しでも再投影誤差が 0.01 px 程度残る(モデルが別物)。詳細な精度比較は未実施 |
| 自前推定(`fovision/calibrate.py`) | 90° 超を含むデータでも真値に一致(場のずれ 1e-12 px 以下) |

結論: `cv2.fisheye` は 90° 未満の点だけに絞れば使えるが、90〜101° の帯を拘束できない。この帯まで使う自前推定を採用する。

## 4. 推定方法

入力はビューごとの「ボード座標の点群」と「検出した画素座標」の組だけで、画像の入力元には依存しない。

1. コーナー検出: `cv2.findChessboardCornersSB`(`fovision/board.py`)。
2. 初期値: fx = fy = 公称焦点距離、主点 = 画像中心、k = 0。
3. ビューごとの姿勢の初期値: 検出点を視線ベクトルに直し、その平均方向が光軸になるよう仮想的にカメラを回してから平面 PnP(IPPE)を解く。90° 前後のボードでも透視投影として扱える。
4. Levenberg-Marquardt で全ビューの再投影誤差を最小化。まず f・主点・姿勢、次に k も解放する 2 段階。
5. 残差とヤコビアンから各内部パラメータの推定標準偏差も出す。

依存は numpy と OpenCV だけ(ヤコビアンは数値微分)。

## 5. 入出力

- 入力元(`fovision/sources.py`): `SimSource`(合成)/ `FileSource`(画像ファイル)/ `CameraSource`(`cv2.VideoCapture`、**未検証**)。どれも (名前, グレースケール画像) を順に返す。
- 出力(`fovision/evaluate.py` の `save_params`): 個体ごとの JSON。

| キー | 内容 |
|---|---|
| `module_id` | モジュール個体の識別子 |
| `source` | `"simulation"` または `"real"`(混ぜない) |
| `model` | 投影モデル名 |
| `image_size`, `fov_deg` | 画像サイズ、全画角 |
| `fx`, `fy`, `cx`, `cy`, `k` | 推定値 |
| `rms_px`, `n_views`, `n_points`, `intr_std` | 再投影誤差 RMS、使ったビュー数・点数、推定標準偏差 |

## 6. 評価方法

- **再投影誤差 RMS**: 実機でも出せる唯一の指標。
- **真値との差**(シミュレーションのみ): fx, fy, cx, cy の差。
- **場のずれ**(シミュレーションのみ): 画角内の各画素を真値モデルで視線に戻し、推定モデルで投影し直したときの画素のずれ。係数同士は打ち消し合うので、モデルとしての良し悪しはこれで見る。入射角 0〜60° / 60〜90° / 90〜101° の帯ごとの最大値も出す。

合格基準は未確定。案として「場のずれの最大値が 1 px 以下」を置いているが、補正後画像の用途から決め直す必要がある。

## 7. シミュレーション結果

`scripts/run_baseline.py`。ボードは内側コーナー 9x6、マス 30 mm、距離 0.15〜0.40 m、傾き 35° まで、ボード中心は画像内に一様に配置。全コーナーが画像内に写る姿勢だけを使う。

### A. 理想コーナー+ガウスノイズ(推定器そのものの精度)

| 25 | 0.1 | cv2.fisheye | 0.18 | 0.25 | 0.56 | (2.21) |

| 25 | 0.3 | cv2.fisheye | 0.52 | 0.74 | 1.68 | (6.63) |
| 25 | 1.0 | 自前 k1〜k4 | 1.19 | 1.29 | 1.90 | (4.29) |
| 25 | 1.0 | 自前 k1〜k2 | 1.17 | 1.24 | 1.29 | (2.60) |

- cv2.fisheye は 88° 以上の点を含むビューを捨てて実行した(25 ビュー中およそ 20 ビューを使用)。そのため 90〜101° は外挿になり、自前推定の約 3 倍以上ずれる。
- 再投影誤差 RMS はどの手法もほぼ同じ(σ=0.3 で 0.41 px)。**再投影誤差だけでは外周の精度差は見えない。**
- 真値が純粋な等距離射影なので、係数が少ない k1〜k2 のほうが外周で安定している。実レンズで k を何個使うかは実機データで決める。
- 推定標準偏差は実際のばらつきと一致した(σ=0.1、30 回試行で cx のばらつき 0.058 px に対し推定値 0.061 px)。

### 処理時間(開発用 Windows PC。Jetson では未計測)

- コーナー検出: 約 0.4 秒/枚
- 推定: 25 ビューで 0.2〜0.3 秒

### 分かっている課題

- **主点の誤差が推定標準偏差より大きい。** 画像を経由した場合、cx の誤差は −0.10〜−0.26 px で、追加の 4 試行では最大 −0.48 px(cy −0.70 px)。推定標準偏差は 0.04〜0.13 px。cx は 10 通りのボード配置(B の 1 通り、C の 5 台、追加の 4 試行)のうち 9 通りでマイナス側。理想コーナーでは偏りが出ない(30 回平均 −0.001 px)ので、推定器ではなく検出側が原因と見ている。検出誤差の全体平均は −0.013 px と小さく、最大 1 px 程度ずれるコーナーが一部にあることまでは確認したが、どのコーナーがなぜずれるかは未特定。
- 90° 超の点を含むビューが少ない(25 ビュー中 2 ビュー)。ボード全体が写る姿勢に限っているためで、外周の拘束を増やすには撮り方の工夫か、部分的に写ったボードを使える検出(ChArUco など)が要る。
- 合成画像は背景も照明も一様で、実画像より検出しやすい。検出率 100% は実機には当てはまらない。

## 8. 実行手順

```
python -m venv .venv
.venv/bin/pip install -r requirements.txt     # Windows は .venv\Scripts\pip
python scripts/check_cv2_fisheye.py           # OpenCV の 90° 超の扱いを確認
python scripts/run_baseline.py                # ベースライン評価(数分)。結果は results/sim/
```

確認した環境: Windows 11、Python 3.13.5、numpy 2.5.5、opencv-contrib-python-headless 5.1.0。contrib は `cv2.omnidir` の確認にだけ使っており、推定本体は通常の OpenCV で動く。
