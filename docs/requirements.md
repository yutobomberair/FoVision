# 要求仕様(案): 顧客側で行うセンサ個体のキャリブレーション

状態: 草案。「未定」と書いた項目は決まり次第埋める。数値の合格基準はすべて案で、根拠となる実験はまだ無い。

関連文書: 投影モデルと推定方法は `docs/spec.md`、ツールの操作は `docs/tool.md`、ボードなし手法の調査は `docs/targetless_survey.md`。

## 1. 背景と目的

- 駐車監視機能付きイメージセンサの PoC を Jetson 上に実装する。製品そのものはまだ無い。
- 顧客は同系統のセンサを自分で用意し、その RAW 画像を PoC に入力して機能を評価する。
- 顧客のセンサにはレンズと組み付けの個体差がある。**顧客が自分の手で、自分のセンサ個体をキャリブレーションできるようにする**のがこの仕様の目的。

## 2. キャリブレーション結果の使い道

- 補正後の画像は**認識**に使う。画像の**全面**を使う。
- キャリブレーションの役割は、個体差のある画像を「認識処理が前提にしている基準の見え方」に揃えること。個体のパラメータから対応表を作り、どの個体の画像も同じ幾何に変換してから認識に渡す。
- 基準の見え方(認識に渡す画像の投影方式・画角・解像度)は未定。認識が魚眼画像をそのまま使うのか、補正後の画像を使うのかで決まる。

## 3. 登場人物と前提

| 項目 | 内容 |
|---|---|
| 作業者 | 顧客の技術者。カメラ校正の専門知識は前提にしない |
| 場所 | 顧客の拠点(机上または実験室)。当方は立ち会わない |
| 実行環境 | PoC の Jetson。画面なし(SSH)でも使えること |
| 入力 | 顧客のセンサの RAW 画像。形式は未定(ビット深度、Bayer 配列、パック形式、ファイルかストリームか) |
| 頻度 | センサ個体ごとに 1 回。やり直しもできること |
| 対象センサ | 魚眼、1920x1536、FoV 202°。同系統の別型番を許すかは未定 |

## 4. 要求

### 4.1 機能

1. RAW 画像を入力として、その個体のカメラパラメータ(fx, fy, cx, cy, k1〜k4)を推定する。
2. 推定結果を個体の識別子つきで保存し、PoC の認識処理がそれを読み込んで使える。
3. 結果の良否を作業者に**合格 / 不合格**で示す。不合格のときは、何をやり直せばよいか(撮り足す場所、枚数、動かし方)を示す。
4. レンズの設計値を入力させない。顧客に公称値を渡さなくても動くこと(現状のツールは対応済み)。
5. 補正後の画像を出力して、作業者が目で確認できる。

### 4.2 手順の手軽さ

顧客が自力でやるので、準備と作業の手間が最も重い制約になる。候補は次の 3 つ。

| 方式 | 顧客が用意するもの | 作業 | 現状 | 懸念 |
|---|---|---|---|---|
| a. 印刷したチェッカーボード | 印刷物と平らな板 | ボードを動かしながら 20〜30 枚撮る | ツール実装済み(合成画像で確認) | 印刷と貼り付けの手間。反りがあると精度が落ちる |
| b. モニタに表示したチェッカーボード | PC やタブレットの画面 | a と同じ | a のツールがそのまま使える見込み。未確認 | 画面の映り込み、モアレ。画面が小さいと外周を埋めにくい |
| c. ボードなし(センサを手で動かす) | 模様のある室内 | センサを持って 10〜20 秒ほど向きを変えながら動かす | 点レベルの試算のみ。画像からの特徴点追跡は未実装 | 動かし方が悪いと決まらない。失敗を自動で見分ける仕組みが要る |

- 内部パラメータの推定にマスの実寸は影響しない(ボードまでの距離の推定値が変わるだけ)。b で画面の大きさを測る必要は無い。
- 駐車監視は設置後にカメラが動かない。c は設置前に手で動かせる段階で行う前提になる。設置後の自動校正は対象外とする(未定)。

### 4.3 精度(案)

| 指標 | 基準(案) | 測れる場面 |
|---|---|---|
| 再投影誤差 RMS | 0.5 px 以下 | 実機・シミュレーション |
| コーナー(または特徴点)が届いた最大入射角 | 画像に写る範囲の 85% 以上 | 実機・シミュレーション |
| コーナーのある区画 | 画像を 8x6 に分けた区画の 70% 以上 | 実機・シミュレーション |
| 真値モデルとのずれの最大(全面) | 2 px 以下 | シミュレーションのみ |

- 実機では真値が無いので、合否は上 3 行で判定する。再投影誤差だけでは外周の精度不足を見逃すため、分布の条件を必ず併用する。
- 「2 px 以下」は仮置き。認識がどれだけの幾何ずれまで耐えるかで決めるべきで、認識処理に意図的にずれを与えて性能低下を測る実験が要る。

### 4.4 処理時間(案)

- 撮影から合否が出るまで 5 分以内(未定)。Jetson での実測値はまだ無い。

### 4.5 配布と機密

- 顧客に渡すのはツールと手順書。レンズのデータシート値は含めない。
- 依存は numpy と OpenCV のみとし、Jetson の標準環境で動かす。

## 5. 対象外

- カメラの取り付け位置と向き(外部パラメータ)の校正。認識結果を車両座標に変換する必要が出たら別途扱う。
- 色、明るさ、周辺減光の補正。
- 認識処理そのもの。

## 6. 未定事項(決める順)

1. RAW の形式と受け渡し方法。
2. 認識に渡す画像の形(魚眼のままか、補正後か。補正するならどの投影か)。
3. 顧客に許容してもらえる手順(4.2 の a / b / c のどれか)。
4. 認識が耐えられる幾何ずれ(4.3 の基準の根拠)。
5. 外部パラメータの要否。
6. イメージサークルとセンサの関係(`CLAUDE.md` の未確定事項を参照)。
